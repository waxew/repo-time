# مراحل ساخت Repo Time

## مرحله ۱ — تحلیل ویدیو

- مشخصات ویدیو با ابزار Media بررسی شد.
- ۱۸ دقیقه و ۲۷ ثانیه محتوا به ۱۴۰ نمای زمانی تقسیم شد.
- صفحات، منوها، Modalها، فرم‌ها و حالت‌های Empty/Success استخراج شدند.
- پالت اصلی سفید، خاکستری، مشکی، بنفش و صورتی ثبت شد.

## مرحله ۲ — طراحی معماری

- Frontend با React و TypeScript انتخاب شد.
- Backend در Route سروری `/api/workspace` متمرکز شد.
- Cloudflare D1 برای داده‌های ماندگار انتخاب شد.
- Drizzle برای تعریف Schema و Migration استفاده شد.
- هویت کاربر از Header امن میزبان خوانده می‌شود و در اجرای محلی حساب Demo وجود دارد.

## مرحله ۳ — مدل داده

پنج جدول ساخته شد:

1. `customers`: پرونده و گروه مشتری
2. `services`: خدمت، مدت و قیمت
3. `appointments`: نوبت، وضعیت، تاریخ و یادآوری
4. `messages`: متن، گیرنده، کانال و وضعیت صف
5. `reviews`: امتیاز و نظر رضایت‌سنجی

تمام جدول‌ها `owner_key` دارند تا اطلاعات صاحبان کسب‌وکار از هم جدا بماند.

## مرحله ۴ — طراحی گرافیکی

- Mobile-first و RTL
- داشبورد مشکی با کارت‌های دو ستونه
- Surface سفید با Border و Radius نرم
- CTA گرادیان بنفش به صورتی
- Bottom Navigation ثابت با دکمه + مرکزی
- Bottom Sheet برای فرم‌ها
- Responsive چهارستونه برای دسکتاپ
- Focus، Disabled و Reduced Motion برای دسترس‌پذیری

## مرحله ۵ — قابلیت‌های تعاملی

- تعویض صفحه بدون Refresh
- تقویم و فیلتر روز
- ثبت مشتری، خدمت و نوبت
- ساخت پیام و محاسبه کاراکتر
- جست‌وجوی زنده
- پرونده مشتری
- فیلتر گروه‌ها
- Toggleهای یادآوری و تنظیمات
- اعلان و Toast موفقیت

## مرحله ۶ — Build و انتشار

- Migration توسط Drizzle تولید می‌شود.
- Vinext کد Next/React را به Worker سازگار تبدیل می‌کند.
- Build باید `dist/server/index.js` و Manifest صحیح تولید کند.
- Migration همراه خروجی به میزبان می‌رود.
- نسخه نهایی بعد از Build موفق منتشر می‌شود.

## مرحله ۷ — GitHub و ZIP

- سورس، مستندات، Lockfile و Migration در GitHub نگهداری می‌شوند.
- پوشه‌های بزرگ یا ماشینی مثل `node_modules`، `dist` و Cache وارد GitHub/ZIP نمی‌شوند.
- ZIP سورس قابل باز کردن، نصب و Build مجدد است.
