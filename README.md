# Repo Time — سامانه مدیریت نوبت و مشتری

Repo Time یک وب‌اپلیکیشن فارسی و راست‌به‌چپ برای مدیریت نوبت، تقویم کاری، پرونده مشتری، خدمات، پیام‌های یادآوری، رضایت‌سنجی و گزارش‌های کسب‌وکار است. رابط آن با بررسی کامل ویدیوی مرجع ۱۸ دقیقه و ۲۷ ثانیه‌ای طراحی شده، اما نام، لوگو و دارایی‌های گرافیکی آن مستقل و متعلق به Repo Time هستند.

## چه چیزهایی در این نسخه کار می‌کند؟

- داشبورد امکانات با کارت‌های نوبت‌دهی، مشتریان، پیامک، رضایت‌سنجی و گزارش
- تقویم ماهانه، فیلتر روز، خلاصه درآمد روز و فهرست نوبت‌ها
- فرم ثبت نوبت با انتخاب مشتری، خدمت، تاریخ، ساعت و یادآوری
- ثبت مشتری، گروه‌بندی مشتریان، جست‌وجو و نمایش پرونده
- تعریف خدمت با مدت، قیمت و رنگ اختصاصی
- ساخت پیام گروهی، محاسبه تعداد کاراکتر/گیرنده و ثبت در صف ارسال
- صفحه‌های شماره اختصاصی، پیامک منطقه‌ای، تبریک تولد، بازگشت مشتری و یادآوری ترمیم
- رضایت‌سنجی، باشگاه مشتریان، قرعه‌کشی، بسته پیامکی و رزرو آنلاین
- گزارش‌های سیستم، تراکنش‌ها، حسابداری مالی و پروفایل
- ذخیره‌ی مشتری، خدمت، نوبت و پیام در Cloudflare D1
- رابط واکنش‌گرا برای موبایل، تبلت و دسکتاپ

## فناوری‌های استفاده‌شده

| فناوری | کاربرد |
|---|---|
| TypeScript | نوشتن کد با کنترل نوع و خطای کمتر |
| React 19 | ساخت کامپوننت‌ها، فرم‌ها و تعاملات رابط |
| Next.js 16 + Vinext | مسیرها، رندر سرور و خروجی سازگار با Worker |
| Vite 8 | Build سریع رابط و Worker |
| CSS | بازطراحی دقیق رنگ، فاصله، کارت، Responsive و Motion |
| Cloudflare Workers | اجرای Backend بدون سرور سنتی |
| Cloudflare D1 | نگهداری پایدار مشتریان، خدمات، نوبت‌ها و پیام‌ها |
| Drizzle ORM | تعریف Type-safe جدول‌ها و تولید Migration |
| Node.js Test Runner | آزمون Artifact نهایی Worker و Migrationها |

## اجرای پروژه روی لپ‌تاپ

پیش‌نیاز: Node.js نسخه ۲۲ یا بالاتر و Git.

در Windows بهتر است دستورها را داخل **Git Bash** اجرا کنید:

```bash
git clone https://github.com/waxew/repo-time.git
cd repo-time
npm install
npm run dev
```

بعد از اجرای دستور آخر، آدرسی که Terminal نشان می‌دهد را در مرورگر باز کنید. اگر پایگاه‌داده محلی هنوز Migration نشده باشد، رابط با داده‌های نمایشی باز می‌شود؛ محیط منتشرشده D1 واقعی دارد.

## ساخت خروجی Production

```bash
npm run build
npm test
```

پوشه `dist/` هنگام Build ساخته می‌شود. این پوشه خروجی ماشین است، نباید دستی ویرایش شود و لازم نیست وارد GitHub شود؛ هر زمان سورس تغییر کند دوباره ساخته خواهد شد.

## درباره کامنت‌ها

فایل‌های دست‌نویس پروژه داخل `app/`، `components/`، `lib/` و `db/` دارای کامنت‌های فارسی هستند. فایل‌های JSON مانند `package.json` و `package-lock.json` طبق استاندارد JSON امکان کامنت ندارند. فایل‌های تولیدشده مثل `drizzle/meta/*.json` و `dist/` نیز دستی ویرایش یا کامنت‌گذاری نمی‌شوند؛ توضیح دقیق نقش آن‌ها در [راهنمای فایل‌ها](docs/PROJECT_GUIDE_FA.md) آمده است.

## نکته درباره پیامک واقعی

این نسخه متن پیام، گیرندگان، هزینه و صف ارسال را مدیریت و در دیتابیس ذخیره می‌کند. برای ارسال واقعی باید API یک ارائه‌دهنده پیامک قانونی (مانند کاوه‌نگار یا سرویس انتخابی شما)، کلید امن، الگوی پیام و Webhook وضعیت تحویل اضافه شود. هیچ کلید جعلی داخل سورس قرار نگرفته است.
